# When to Activate

计算"某部分在整体中的百分比"，包括但不限于：
- 计算"A 占 B 的百分比"
- 计算某个子集在总体中的占比
- 按维度分别计算各自的占比
- 计算 Top N 合计占比

**典型表述**：
- "A类产品占总销售额的比例是多少"
- "前5名一共占了多少"
- "各部门分别占总收入的百分比"
- "某地区在总成本中的比重"

**关键特征**：需要同时计算"部分"和"整体"，然后求百分比。

# Not For

- 单纯对比增减 → 用 `comparison`
- 单纯排名 → 用 `ranking`
- 单纯看趋势 → 用 `trend`
- 只看各项的绝对值分布、不需要百分比 → 用 `source`

# Disambiguation

- "A类产品占总销售额的比例" → ratio（需要计算百分比）
- "各部门销售额" → 不是 ratio → source（拆解构成，不计算百分比）
- "各部门销售额占比" → ratio（需要计算百分比）
- "销售额最高的产品" → 不是 ratio → ranking
- 需要输出百分比数字 → ratio；只需要输出绝对值 → source

# Planner Prompt

## 占比分析 (ratio)

**适用场景**：计算"A 占 B 的百分比"

**不适用**：
- 单纯对比增减 → `comparison`
- 单纯排名 → `ranking`
- 单纯看走势 → `trend`
- 只看绝对值分布 → `source`

**★ 指标选择优先级**：
1. **优先使用派生指标**：若业务配置中已有 `type: derived` 的比率/占比指标，且含义与当前任务一致，应直接引用该派生指标 ID，系统会自动展开公式
2. **其次使用原子指标列表**：若无匹配的派生指标，metric 用列表 `["分子指标", "分母指标"]`，系统会自动注入各自的筛选条件

**SQL 模式**：系统根据指标定义自动生成聚合表达式

**核心概念**：
占比分析的本质是**计算"部分/整体"的百分比**。

有三种典型输出模式：

| 模式 | 触发词 | 输出形式 |
|------|--------|----------|
| 分别占比 | "分别""各自""每个" | 多行（GROUP BY 维度） |
| 合计占比 | "一共""合计""总共" | 单行 |
| TOP N 占比 | "前N名""TOP N" | N 行（CTE 先取 TOP N，再计算占比） |

**★ 核心原则 — 使用 CTE 隔离分组与全局聚合**：
占比 = 部分 / 整体。当需要同时获取"分组值"和"全局总值"时，**必须使用 CTE**：
- CTE 1: 计算每个分组的值（GROUP BY 维度）
- CTE 2: 计算全局总值（无 GROUP BY）
- 最终 SELECT: 从两个 CTE JOIN 计算占比

**关键决策**：
1. 准确识别**分子条件**（哪部分）和**分母条件**（整体）
2. 系统已将分子/分母逻辑编码在聚合表达式中，使用预定义表达式即可
3. 一个 SQL 算出"部分/总体"比例，不要拆成多个任务

**注意事项**：
1. 核心：一个 SQL 算出"部分/总体"比例，不要拆成多个任务
2. 分母始终用 `NULLIF(分母, 0)` 防止除零
3. 如果用户的分子条件涉及聚合排序（如"销售额前5的产品"），必须用 CTE 先取 Top N

# SQL Instruction

### 占比分析 SQL 生成规则

**核心原则**：占比 = 部分 / 整体，**统一使用 CTE** 将分组聚合与全局聚合隔离在不同子查询中。

**模式选择**（参考下方「SQL 参考示例」中的完整模板）：

| 触发词 | 模式 | 关键结构 |
|--------|------|----------|
| "分别""各自""每个" | 模式1 — 分别占比 | CTE grouped(GROUP BY) + CTE total → CROSS JOIN |
| "一共""合计""总共" | 模式2 — 合计占比 | CTE part(条件筛选) + CTE total → CROSS JOIN |
| "前N名""TOP N" | 模式3 — TOP N 占比 | CTE ranked(LIMIT N) + CTE total → CROSS JOIN |

**关键规则**：
1. 指标虚拟字段用**裸名称**引用（如 `total_flow`），系统自动包裹聚合
2. **禁止**自行构造 CASE WHEN 表达式，使用预定义指标
3. 分母始终用 `NULLIF(<分母>, 0)` 防除零
4. `ROUND(..., 2)` 保留 2 位小数
5. 只生成 1 个 SQL，不拆分

**常见错误**：
- ❌ 自行构造 CASE WHEN 而非使用预定义指标
- ❌ 忘记 NULLIF 导致除零
- ❌ 模式选错（"分别"用了模式2 / "合计"用了模式1）
- ❌ 用窗口函数 `SUM(metric) OVER ()` 计算全局总值（应用 CTE）
